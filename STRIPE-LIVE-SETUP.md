# Timadashouse live Stripe setup

This project uses separate Stripe Checkout flows: appointments collect the fixed **$50 USD deposit** (the remaining balance is paid at the salon), while product purchases collect the **full cart total plus the flat $10 shipping fee**. Product orders and appointment bookings are stored and updated independently.

## Convex environment variables

Set these on the **production Convex deployment**:

```bash
npx convex env set SITE_URL https://www.timadashouseglam.com
npx convex env set ADMIN_EMAILS timadashouse@gmail.com,timadashouse@yahoo.com
npx convex env set STRIPE_SECRET_KEY rk_live_REPLACE_WITH_YOUR_RESTRICTED_KEY
npx convex env set STRIPE_WEBHOOK_SECRET whsec_REPLACE_WITH_YOUR_LIVE_WEBHOOK_SECRET
npx convex env set IMAGEKIT_PRIVATE_KEY private_REPLACE_WITH_YOUR_IMAGEKIT_PRIVATE_KEY
```

Only set `IMAGEKIT_PRIVATE_KEY` if enabling ImageKit uploads. Never put server keys in `VITE_` variables or commit them.

The Stripe code in this project calls `POST /v1/checkout/sessions`. Its restricted Stripe key should have **Checkout Sessions: Write**. It does not directly call the Customers, Products, Prices, or Payment Intents APIs. If you later change the integration, re-evaluate permissions against the API calls actually made.

## Stripe live webhook

Register this endpoint in Stripe Dashboard while **Live mode** is enabled:

```text
https://YOUR-PRODUCTION-DEPLOYMENT.convex.site/timada-stripe-webhook
```

Use the production Convex deployment's `.convex.site` hostname (not the Vercel website URL and not the development deployment hostname).

Subscribe to exactly these Checkout Session events:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`
- `checkout.session.expired`

Copy the signing secret generated for this **live endpoint** (`whsec_...`) into `STRIPE_WEBHOOK_SECRET` on the same production Convex deployment.

## Frontend/Vercel variables

Set these in the Vercel production project:

- `VITE_CONVEX_URL` — production Convex deployment URL ending in `.convex.cloud`
- `VITE_IMAGEKIT_PUBLIC_KEY` — ImageKit public key (only if uploads are enabled)
- `VITE_IMAGEKIT_URL_ENDPOINT` — ImageKit URL endpoint (only if uploads are enabled)

`VITE_CONVEX_SITE_URL` may be present in the local environment generated by the Convex CLI, but the frontend derives the HTTP Actions hostname from `VITE_CONVEX_URL`.

## Webhook behavior in this revision

- Successful paid appointment Checkout sessions confirm the associated pending booking.
- Product purchases use `POST /timada-product-checkout`; the server reloads product prices from the Convex catalogue, creates a pending product order, and sends every cart line plus shipping to Stripe.
- Product webhook events update `timadaProductOrders` independently from `timadaBookings`; product orders never use the $50 appointment deposit.
- `checkout.session.async_payment_succeeded` confirms only when Stripe reports `payment_status=paid`.
- `checkout.session.async_payment_failed` and `checkout.session.expired` cancel a booking only if it is still pending.
- The webhook verifies Stripe's signature and validates the relevant booking/order ID and USD amount (exactly $50 for appointment deposits; full server-calculated order total for products).
- The webhook returns a retryable error if it arrives before the Checkout Session has been attached to its booking.

## Important deployment sequence

1. Deploy the updated Convex functions to the production deployment.
2. Set the production Convex environment variables.
3. Create the live Stripe webhook with the endpoint and events above.
4. Set the generated live `whsec_...` value in production Convex.
5. Send a controlled live test booking only after checking the deployed webhook delivery succeeds and the booking becomes confirmed.

Do not use a development `whsec_...` value for the live endpoint. Keep all live secret values private.
